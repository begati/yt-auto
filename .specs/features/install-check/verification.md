Probed without a finding: `./gradlew testDebugUnitTest --rerun` green (round 2: InstallCheckTest 5/5, I18nTest passes with the 6 strings in 11 locales). Own examples at HEAD (throwaway test, removed): installer `""` warns; `com.android.vending` never warns whatever `ignoredAt`; `notifyInstall` rejects `...gearhead.debug`. Android < 11 (minSdk 29): `getInstallerPackageName` returns the same installer field; a throw there gives `null` and warns, which X can dismiss. A Play Store install of a future release records `com.android.vending` - no warning. `lastUpdateTime` equal across a reinstall would need the same millisecond - not a practical case. X then a KingInstaller reinstall: the pref stays but the installer check alone hides the strip; a later adb install has a new `lastUpdateTime` and warns again. Android 13+ without POST_NOTIFICATIONS: `notify` is dropped by the system without throwing (and `runCatching` covers it) - the guard is still stamped, harmless. The 10-minute guard is a process global (`installNotifiedAt`): a process death between the car-session and media-card bindings can post twice, which only repeats a notice (`setAutoCancel`, same id 1, so it replaces, not stacks). The channel name is read with `getString` on each post and `createNotificationChannel` renames an existing channel, so it follows the device language. The car session `init` runs on every session but goes through `installWarningNow`, so the X is honored. `onResume` -> `checkSignIn` re-reads the install, so coming back from KingInstaller after a reinstall hides the strip. The strip's button uses the same borderless style as the sign-in banner's "Entrar"; with `Theme.DeviceDefault` it may render in capitals, as that one does - not a regression.
